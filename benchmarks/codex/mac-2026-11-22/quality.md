I also checked the held-out answers for CronJob duplication, deadline versus retries, batch-node exclusivity, preemption and PDBs, quota admission, ConfigMap mounts versus environment variables, kubelet eviction under pressure, namespace security modes and service-account credential overrides. These are targeted checks on an open-ended memo. There is no all-claims accuracy score or independent blinded reviewer for those memos.

## What the agents did

Some combined the ledger read and several Office reads into one shell invocation. The indexed runs found the ledger or receipt, joined them on the seal, compared document editions, and searched for any record of approval. The extra checks did not improve the exact-answer score on this task.

In the 0.14.3 trials, two Finnish runs each submitted three bare workbook paths in a multi-read; the surrounding command succeeded but those individual reads returned errors. A command exit code alone would miss them. The 0.14.4 Finnish lexical runs had zero partial-read errors. Another run's long ledger excerpt narrowed to its matching record but the earlier implementation named the whole 152-line chunk. The regression now reads the emitted range back from the original.

GBrain's third lexical run combined many searches and linked-source reads into 14 shell calls. Its first two used 59 and 55 calls. All three completed the audit; the third had one unsuccessful grouped command. Meme also combined multiple commands. Comparing shell counts across these runs would give a misleading estimate of provider model rounds. The runner now publishes rounds only when their token sums reconcile with the provider turn.
