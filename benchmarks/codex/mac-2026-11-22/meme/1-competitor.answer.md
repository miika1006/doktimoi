**Decision: revise before production approval.** The proposed fields provide useful controls, but do not establish end-to-end availability, request completion, database resilience, or data protection. The recommendations below distinguish documented behavior from configuration choices and validation requirements.

1. **The PDB does not guarantee five replicas in all three cases.** Node failure is involuntary: PDBs cannot prevent it, although unavailable Pods count against the budget. A normal `kubectl drain` uses eviction requests, which respect the PDB and may block pending recovery; direct deletion bypasses this protection. Deployment rolling updates count against the budget but are not constrained by it. Thus, six replicas with `maxUnavailable: 2` permit four available during rollout. Recommend `maxUnavailable: 0`, `maxSurge: 1`, with capacity for the extra Pod; `maxUnavailable: 1` also matches a five-replica rollout floor at six desired replicas. Neither configuration prevents concurrent failures. 2. **Explicitly spread the API across zones.** Use a matching application selector, `topologyKey: topology.kubernetes.io/zone`, and `maxSkew: 1`, targeting two replicas per zone. The topology key groups nodes by label value. With `DoNotSchedule`, skew limits the difference between the target domain’s count and the global minimum; violating placements remain pending. `ScheduleAnyway` favors reduced skew without enforcing it. Zone-loss behavior depends on which domains remain eligible: unavailable domains still counted can block replacements; domains disappearing from eligibility change the calculation. Constraints also do not guarantee balance after removals. 4. **Thirty seconds does not guarantee request completion.** The grace-period clock starts before `preStop`; the hook consumes that budget. After the hook, the runtime normally sends SIGTERM to the main process. Remaining processes receive SIGKILL when grace expires; an unfinished hook can receive a small, one-off two-second extension. Endpoint processing proceeds concurrently: terminating EndpointSlice entries are not immediately removed, but have `ready: false`; `serving` supports draining-aware consumers. Implement shutdown that stops accepting work and finishes existing requests, then size grace for measured hook and drain duration. The docs establish neither instantaneous traffic convergence nor completion of arbitrarily long requests. 6. **HPA deliberately moderates the raw ratio.** Its basic calculation is the ceiling of current replicas multiplied by current/target metric. Missing metrics are initially set aside, then conservatively assumed at 100% of target for downscale and 0% for upscale. Not-yet-ready CPU Pods are also set aside and assumed at 0% when damping an upscale. Recalculation can suppress scaling if it reverses direction or falls within tolerance, default 10%. Consequently, displayed utilization and actual scaling can differ. Resource metrics availability is a prerequisite.
