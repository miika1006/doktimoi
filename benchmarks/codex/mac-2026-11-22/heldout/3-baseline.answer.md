**Decision memo:** Approve only after resolving the conflict between exclusive batch nodes and yielding capacity to interactive services. The proposed controls support the platform, but do not guarantee exactly-once reports, immediate preemption, or application-safe configuration changes.

1. **CronJob scheduling is approximate.** Kubernetes can create two Jobs or none for a scheduled execution; reports therefore need application-level idempotency. `concurrencyPolicy: Allow` permits overlap; `Forbid` skips an occurrence while the previous Job remains unfinished, although a later start may remain possible within its deadline; `Replace` replaces the unfinished run. These policies cover only Jobs from the same CronJob. Choose `Forbid` if overlapping reports are unacceptable. ([cron-jobs.md, lines 130–143](/private/var/folders/3t/t35161bs2slggt46tnrk0b4c0000gn/T/doktimoi-bench-3-baseline-ZN4NHs/docs/concepts/workloads/controllers/cron-jobs.md:130), [lines 213–217](/private/var/folders/3t/t35161bs2slggt46tnrk0b4c0000gn/T/doktimoi-bench-3-baseline-ZN4NHs/docs/concepts/workloads/controllers/cron-jobs.md:213))

   `startingDeadlineSeconds` limits lateness in **starting**, not runtime; expired occurrences are skipped. Values below ten seconds may prevent scheduling. More than 100 missed schedules prevents Job creation; setting a deadline bounds the missed-schedule counting window. `Forbid` skips count as misses. Set `.spec.timeZone` explicitly, such as `Etc/UTC`; otherwise the controller manager’s local zone applies. ([cron-jobs.md, lines 109–126](/private/var/folders/3t/t35161bs2slggt46tnrk0b4c0000gn/T/doktimoi-bench-3-baseline-ZN4NHs/docs/concepts/workloads/controllers/cron-jobs.md:109), [lines 180–186](/private/var/folders/3t/t35161bs2slggt46tnrk0b4c0000gn/T/doktimoi-bench-3-baseline-ZN4NHs/docs/concepts/workloads/controllers/cron-jobs.md:180), [lines 228–240](/private/var/folders/3t/t35161bs2slggt46tnrk0b4c0000gn/T/doktimoi-bench-3-baseline-ZN4NHs/docs/concepts/workloads/controllers/cron-jobs.md:228))

2. **Bound retries and total runtime separately.** `restartPolicy: OnFailure` restarts failed containers within their Pod; `Never` lets container failure fail the Pod, which the Job controller can replace. `backoffLimit` defaults to six, with exponential replacement delays; counting includes failed Pods and, for `OnFailure`, container retries. ([job.md, lines 318–329](/private/var/folders/3t/t35161bs2slggt46tnrk0b4c0000gn/T/doktimoi-bench-3-baseline-ZN4NHs/docs/concepts/workloads/controllers/job.md:318), [lines 358–374](/private/var/folders/3t/t35161bs2slggt46tnrk0b4c0000gn/T/doktimoi-bench-3-baseline-ZN4NHs/docs/concepts/workloads/controllers/job.md:358))

   Set Job-level `activeDeadlineSeconds` for the hours-long execution budget. It takes precedence over remaining retries, terminates running Pods, and fails the Job with `DeadlineExceeded`; backoff exhaustion can fail it earlier. Failed Jobs do not automatically restart. `ttlSecondsAfterFinished` controls subsequent cleanup of completed or failed Jobs and dependent Pods, not execution duration. ([job.md, lines 623–663](/private/var/folders/3t/t35161bs2slggt46tnrk0b4c0000gn/T/doktimoi-bench-3-baseline-ZN4NHs/docs/concepts/workloads/controllers/job.md:623), [lines 737–775](/private/var/folders/3t/t35161bs2slggt46tnrk0b4c0000gn/T/doktimoi-bench-3-baseline-ZN4NHs/docs/concepts/workloads/controllers/job.md:737))

3. **Use both exclusion and attraction.** Taint batch nodes, for example `dedicated=batch:NoSchedule`; give batch Pods the matching toleration **and required node affinity** to batch labels.    `NoSchedule` leaves existing Pods running; `NoExecute` also evicts intolerant residents, with `tolerationSeconds` permitting temporary tolerance. 4. **Give interactive services higher priority.** A cluster-scoped PriorityClass maps a name to an integer priority. Assign lower priority to batch and optionally `preemptionPolicy: Never`, preventing batch from preempting others while leaving it preemptible. Interactive workloads need `PreemptLowerPriority` to preempt.    Preemption helps only where removing lower-priority Pods makes a node suitable. Victims receive graceful termination, delaying capacity release. PDB protection is best effort: preemption can violate it. ([pod-priority-preemption.md, lines 187–194](/private/var/folders/3t/t35161bs2slggt46tnrk0b4c0000gn/T/doktimoi-bench-3-baseline-ZN4NHs/docs/concepts/scheduling-eviction/pod-priority-preemption.md:187), [lines 216–238](/private/var/folders/3t/t35161bs2slggt46tnrk0b4c0000gn/T/doktimoi-bench-3-baseline-ZN4NHs/docs/concepts/scheduling-eviction/pod-priority-preemption.md:216))

5. **Quota is admission control, not reserved capacity.** Specify CPU and memory requests and limits for every container. Precisely, `requests.*` quotas require corresponding requests; `limits.*` quotas require corresponding limits. Quota-violating creation or updates receive HTTP 403, rather than admitting a Pod to wait for quota. Quota changes do not affect already-created resources, including running Pods. Aggregate quotas can exceed cluster capacity and create contention. ([resource-quotas.md, lines 26–60](/private/var/folders/3t/t35161bs2slggt46tnrk0b4c0000gn/T/doktimoi-bench-3-baseline-ZN4NHs/docs/concepts/policy/resource-quotas.md:26), [lines 74–77](/private/var/folders/3t/t35161bs2slggt46tnrk0b4c0000gn/T/doktimoi-bench-3-baseline-ZN4NHs/docs/concepts/policy/resource-quotas.md:74), [lines 464–469](/private/var/folders/3t/t35161bs2slggt46tnrk0b4c0000gn/T/doktimoi-bench-3-baseline-ZN4NHs/docs/concepts/policy/resource-quotas.md:464))

6. **Choose configuration consistency deliberately.** Ordinary ConfigMap volume projections update eventually; delay can reach the kubelet sync period plus cache propagation delay. `subPath` mounts receive no updates. Environment variables require Pod restart. File projection does not establish that the reporting application reloads settings correctly. ([configmap.md, lines 191–208](/private/var/folders/3t/t35161bs2slggt46tnrk0b4c0000gn/T/doktimoi-bench-3-baseline-ZN4NHs/docs/concepts/configuration/configmap.md:191))

   Prefer a versioned immutable ConfigMap per report configuration when reproducibility matters. Immutability cannot be reversed and its data cannot be edited; replacement is necessary. Deleting and recreating the same name leaves existing mount points, so the docs recommend recreating consuming Pods. ([configmap.md, lines 299–328](/private/var/folders/3t/t35161bs2slggt46tnrk0b4c0000gn/T/doktimoi-bench-3-baseline-ZN4NHs/docs/concepts/configuration/configmap.md:299))

7. **Memory-pressure eviction is not simply lowest-priority-first.** After node resource reclamation proves insufficient, kubelet ranks Pods by whether usage exceeds requests, then priority, then usage relative to requests. BestEffort/Burstable Pods exceeding requests go before Pods within requests; QoS class itself is not the selection mechanism. Therefore low batch priority alone does not guarantee batch-first eviction. ([node-pressure-eviction.md, lines 318–342](/private/var/folders/3t/t35161bs2slggt46tnrk0b4c0000gn/T/doktimoi-bench-3-baseline-ZN4NHs/docs/concepts/scheduling-eviction/node-pressure-eviction.md:318))

   Node-pressure eviction does not honor PDBs or guarantee the Pod’s configured termination grace. Hard thresholds mean immediate termination; soft thresholds use the kubelet eviction grace configuration, which can shorten or eliminate grace. ([node-pressure-eviction.md, lines 26–36](/private/var/folders/3t/t35161bs2slggt46tnrk0b4c0000gn/T/doktimoi-bench-3-baseline-ZN4NHs/docs/concepts/scheduling-eviction/node-pressure-eviction.md:26), [lines 187–197](/private/var/folders/3t/t35161bs2slggt46tnrk0b4c0000gn/T/doktimoi-bench-3-baseline-ZN4NHs/docs/concepts/scheduling-eviction/node-pressure-eviction.md:187))
